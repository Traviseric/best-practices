## BLOCKER

### B1. `skills/verification-gate/SKILL.md:3` — frontmatter is not valid YAML; the skill will not parse
Class: FRONTMATTER.

The `description:` value is an unquoted plain scalar containing four `: ` (colon-space) sequences. YAML reads the first one as a nested mapping key and aborts:

```
mapping values are not allowed here, line 2, column 107
... right before it leaves your hands: a filing, a grant or contract ...
```

The four offending sequences are `...leaves your hands: a filing`, `...(SOURCE: it traces`, `...FIDELITY: every quote`, `...FITNESS and CURRENCY: the source`.

`name` matches the folder (`verification-gate`) and the description is **969 characters**, under the 1024 limit — length is not the problem, quoting is. Fix by switching to the block-scalar form already used correctly in `skills/session-closeout/SKILL.md:3` (`description: >-`), or by quoting the string.

### B3. `docs/PRE_COMMIT_BUILD_GATE.md:19-40` — the build-gate wiring is wrong in two independent ways, and it is the exact defect the philosophy essay says was fixed
Class: CONTRADICTION / BROKEN REFERENCE.

The JSON at lines 19-38 puts `"if": "Bash(git commit:*)"` on the **matcher group**, as a sibling of `matcher` and `hooks`:

```json
{
  "matcher": "Bash",
  "if": "Bash(git commit:*)",
  "hooks": [ { "type": "command", ... } ]
}
```

`if` is a field on the **individual hook entry**, not on the group (Claude Code hooks reference: "`if` field: Further filter tool calls using permission rule syntax"). The repo's own two other copies of this hook get it right — `hooks/hooks.json:10,17` and `templates/settings.json.template:27,39,51` all place `"if": "Bash(git commit *)"` inside the hook entry. As written in `PRE_COMMIT_BUILD_GATE.md` the key sits where nothing reads it, so the gate fires on **every Bash tool call**, not only on `git commit` — which directly contradicts that same file's own claim at line 62 ("**The hook only triggers on `git commit`** — normal development isn't slowed"), and is the defect `philosophy/lighting-the-abyss.md:48` and `skills/lamps/SKILL.md:72` both report as found and "fixed the same day."

Second, incompatible defect in the same block: line 40 says the command must output `{"continue":false,"reason":"<why>"}` to block, while `hooks/build-gate.example.json:36` and `templates/settings.json.template:28` emit `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny",...}}`, and both shipped guard scripts (`hooks/guard-staged-secrets.sh:33-38`, `hooks/guard-conflict-markers.sh:21-26`) emit the `hookSpecificOutput` form. Three files document one protocol; one file documents another. A reader who follows `PRE_COMMIT_BUILD_GATE.md` gets a hook that runs constantly and halts the whole session instead of denying one tool call.

Third, smaller, inside the same defect: the scoping string differs too — `Bash(git commit:*)` here versus `Bash(git commit *)` everywhere else. Pick one.

## Verdict

**Coherent in its spine, incoherent at its edges.**

The eight skills, the eight philosophy entries, `SEVEN_CHEAP_LIES`, `ENGINEERING_PRINCIPLES`, `WEB_DESIGN_PRINCIPLES`, `HOOKS`, `ROOM_AND_GROUND`, `INSIGHTS`, and both guard scripts are one voice, one standard, and demonstrably field-tested — the guards do what they claim under independent reproduction, and the incidents are specific enough to be falsifiable. That is most of the repository by weight and all of it by value.

What is not coherent is the seam between that spine and the six older general-purpose docs (S6), which were plainly written to a different standard and never brought up to it; the four places that still describe a five-skill kit (S1); the build-gate doc that contradicts the three other copies of its own hook and ships the exact bug the philosophy claims was fixed (B3); the two skills whose frontmatter does not parse (B1, B2); the two skills that depend on files the documented installer does not install (B4); and the navigation layer, where 20 of 32 files — including three of eight skills and four of eight philosophy essays — sit off the path entirely (B6).

None of that is the parallel-agent assembly showing as sloppiness. It shows as *unswept*: a strong core written last, and an older layer plus a set of cross-file counts that nobody walked end to end until now. Six blockers, all cheap to fix, and the repo would be coherent.
